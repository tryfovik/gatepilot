# GatePilot Console

GatePilot Console 是独立 Vue 前端模块，只调用 `gatepilot-apiserver` REST/JSON API，不直接访问 proxy、数据库或后端配置文件。

## 本地运行

```bash
npm install
npm run dev
```

默认地址：

```text
http://127.0.0.1:5174
```

## 设计约束

- 默认中文优先，`zh-CN` 是首个 locale。
- 风格走成熟运维控制台路线，保持克制、清晰、便于排障。
- 页面请求收口到 `src/api`。
- 页面文案收口到 `src/i18n`。
- 新页面先补页面目标、参考系统、主流程和状态设计，再写代码。

## 前端改造计划

### 改造目标

GatePilot Console 要做成平台网关的管理面，不做炫技页面。页面必须能支撑日常接入、发布、排障和审计，不能只有展示，也不能出现大量“看起来能点但没有动作”的按钮。

### 设计参考

- 参考 Kubernetes Dashboard、Nacos Console、阿里云 ACK / MSE 这类成熟控制台的信息组织方式
- 页面风格保持克制、专业、统一，优先让数据关系清楚、操作路径短、错误原因可见
- 复杂配置用向导、模板、分组表单和预览承接，避免把原始资源字段直接甩给用户

### 基础规则

- Console 路由采用三层结构：一级业务域、二级能力分组、三级具体页面，例如 `/platform/organization/namespaces`
- 菜单名称要短，页面标题要清楚。左侧菜单用“项目管理、路由目录、上游服务、配置发布”这类短名称，页面标题和说明再补足业务含义
- 左侧菜单必须支持侧栏收起和分组折叠，默认只展开当前业务分组，避免导航字太多、页面压迫感太强
- 响应式布局在平板宽度仍保持左侧导航，不把侧栏改成顶部大块导航，避免页面区域割裂
- 菜单、顶部标题、内容卡片和表单字号必须保持同一套层级，不能出现页面内外像两套系统
- 平台配置类资源必须拆成独立页面，不允许全部塞进“设置”页；“平台配置总览”只做入口导航，不承担具体 CRUD
- 平台配置资源页以列表为主，新增/编辑使用居中弹窗，行内提供查看、编辑、删除，相关同组配置入口默认折叠
- 普通资源详情使用右侧抽屉，保留列表上下文；复杂详情如果包含多 Tab、版本对比或长流程操作，必须拆成独立详情页
- 平台配置资源的唯一标识不单独拆页，必须在当前资源页按业务语义命名，例如环境编码、团队编码、分片编码，并提供说明气泡
- 旧短路由只作为兼容重定向保留，页面内跳转必须使用新的三层路由
- 命名空间、团队、环境、配置分片、隔离组、流量等级、入口域名必须是可创建、可选择、可查看的资源，不能只是输入框
- 后端可调参数必须建模成动态参数资源，Console 保存后由后端热生效，不能做成只改 `application.yml` 的重启参数
- 参数配置要同时支持推荐默认值和高级全量配置，像 Helm values 一样能默认掉大部分字段，也能展开完整字段
- 参数旁边要有说明提示，鼠标悬停可以看到参数含义、影响范围和默认值
- 项目、路由、上游、策略、发布和诊断要能按命名空间联动筛选
- 所有按钮必须有真实动作、禁用原因或明确反馈
- 列表不能展示“未知”和错误的 1970 时间，后端缺字段时前端要给出合理业务态
- 资源中心的数量必须能追到明细，用户看到“14 个资源”时可以直接知道是哪 14 个、属于哪个命名空间、最近是否变更
- 所有页面的数字、状态、摘要都必须可解释或可下钻，用户看到项目数、异常数、节点数、版本数、错误率时，要能继续看到明细来源和下一步操作
- 指标卡片不能只做展示，能点击就进入明细，不能点击就要在同页给出明细列表、最近记录或解释文案
- 接入向导尽量选择已有基础资源，只有项目名、路径、上游地址这类项目私有信息才允许自由输入
- 治理和发布能力要用用户语言表达，例如“限流保护上游”“灰度切流”“候选版本”，避免直接展示后端字段名
- 请求量会很大的列表必须分页查询，不能一次拉全量，审计、节点、资源列表都要保留 cursor 或下一页能力
- 运行审计是旁路能力，proxy 主请求链路只允许轻量采集并写入内存队列，写库和上报必须异步批量、可降级、可丢弃，不能阻塞转发
- 蓝绿、灰度、染色这类能力要按用户任务组织，少暴露生硬枚举
- 页面数据统一走 `src/api`，时间、状态、枚举展示统一走工具方法
- Console 只调用 apiserver API，不直接访问数据库、agent 或 proxy
- 部署服务器为 GatePilot 专用环境，可以清理旧 GatePilot 进程、旧包和旧部署目录；清理前必须列出目标路径确认，不把服务器密码写入仓库文档

### 路由命名规范

Console 的路由必须让用户从 URL 和菜单名判断自己所在的业务位置：

- 工作台：`/workbench/runtime-overview`
- 接入管理：`/access/project-onboarding`、`/access/gateway-projects/project-list`
- 流量配置：`/traffic/routing/route-catalog`、`/traffic/upstream/upstream-services`、`/traffic/governance/policy-center`
- 发布管理：`/release/config-release/release-center`、`/release/version-snapshots/snapshot-list`
- 运行观测：`/runtime/config-state/published-configs`、`/runtime/data-plane/node-instances`、`/operations/route-diagnostics/request-workbench`、`/operations/runtime-audit/audit-records`、`/operations/control-plane-events/event-list`
- 平台配置：`/platform/resources/resource-center`、`/platform/organization/namespaces`、`/platform/organization/teams`、`/platform/organization/environments`、`/platform/organization/ingress-domains`、`/platform/capacity/config-shards`、`/platform/capacity/isolation-groups`、`/platform/capacity/traffic-tiers`、`/platform/runtime/control-plane-settings`、`/platform/settings/overview`
